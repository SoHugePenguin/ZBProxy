# 网站配置入口、出口与玩家分流

启动 `zbproxy` 后访问 `Web.Bind` / `Web.Port` 对应的管理地址，使用现有管理账号登录。原有 `Services`、`Outbounds` 和简单的 `ServiceName` 路由会自动读取到表单。无需手工编辑 JSON。

## 配置顺序

1. 在“出口线路”添加出口，填写目标 Minecraft 服务器和端口。连接方式可选直连、SOCKS5、HTTP CONNECT、SOCKS4 或 SOCKS4a。需要认证时填写代理用户名和密码。
2. 在“入口端口”添加监听地址、端口和默认出口。同一端口可供多个玩家使用。需要加密时启用 Trojan / TLS，填写服务器上已有的证书、私钥路径和连接密码。
3. 在“玩家分流”添加玩家名或 UUID、适用入口和指定出口。未匹配的玩家走入口默认出口；默认出口也可选择拒绝连接。
4. 在“白名单”管理允许登录的玩家。分流规则本身不授予白名单权限。

已有入口、出口的名称用作引用，编辑时保持固定。更名可先新建配置、调整引用，再删除旧配置。删除仍被入口或玩家规则引用的出口会被拒绝。

入口的默认出口也可以选择“沿用原有路由”，继续使用已有 `Router.Rules` 和全局默认出口。旧路由未导入为入口默认出口时，仍可直接添加或修改出口；编辑入口不会自动将它改到列表中的第一条线路。原有路由仍在引用的出口也不能直接删除。

## 生效与保存

保存会验证配置、准备出口并检查监听端口，然后以原子替换方式更新原来的 `ZBProxy.json`。原有网页设置、`EncryptionClient` 等其他根配置字段会保留。配置包含代理密码，应继续放在受保护的配置目录中。

代理密码和入口连接密码不通过读取接口返回；页面显示是否已设置。密码留空时保留原值，代理密码也可显式清除。改为直连会清除该出口的代理密码。

玩家规则和出口更新用于新连接，已有连接继续使用原线路。只改线路不重建入口监听。改变监听地址、端口或 TLS 配置时会重建相应入口；失败时尝试恢复原监听，错误会显示在页面。配置文件写入失败时也会恢复原监听。

多个页面同时编辑时使用配置版本检查，避免覆盖其他页面的保存。外部编辑配置文件仍支持自动重载，目录监听可识别连续多次原子替换；网站自身的保存不会重复重载。网页监听地址和管理账号仍在进程启动时读取。

## 玩家匹配

匹配优先级是 UUID、玩家名；同种方式下，指定入口的规则优先于“全部入口”。玩家名不区分大小写。UUID 接受带连字符和不带连字符的写法。

1.8.9 等旧客户端的登录包不携带 UUID，应选择玩家名。网站不在线查询 UUID，登录转发不依赖额外的账号服务。这里识别的是客户端提交的身份字段，不能视为已认证身份；正版身份仍由目标游戏服务器验证。

服务器列表查询没有玩家名，使用入口默认出口的 MOTD。指定出口故障时会连接失败，不会自动切换其他出口或直连。

## 线路测试

出口支持单条测试和顺序批量测试，每条最多采样三次，整个测试最多 12 秒，并限制同时运行的测试数量。

- TCP 连接：包含到代理、代理认证及通过代理连接目标服务器的耗时。
- Minecraft Ping：先经过实际出口连接目标服、读取 MC 状态，再发送 Ping 并核对返回内容；统计 Ping 请求与响应的往返时间。

显示成功次数、平均耗时、每次结果、失败原因和测试时间。结果只保留在当前页面，保存配置后清空，避免误读为新配置的结果。

测试从运行 ZBProxy 的机器发起，不包含玩家到该机器的网络延迟。TCP 或 Ping 成功不代表完成了正版登录。自定义 `Dialer` 拨号链暂不支持网站测速。
